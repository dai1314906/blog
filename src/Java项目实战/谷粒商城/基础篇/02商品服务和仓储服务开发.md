```java
@Override
public List<CategoryEntity> listWithTree() {
    //1、查出所有分类
    List<CategoryEntity> entities = baseMapper.selectList(null);
    //2、组装成父子的树形结构
    //2.1）、找到所有的一级分类
    List<CategoryEntity> level1Menus = entities.stream().filter(categoryEntity ->
         categoryEntity.getParentCid() == 0
    ).map((menu)->{
        menu.setChildren(getChildrens(menu,entities));
        return menu;
    }).sorted((menu1,menu2)->{
        return (menu1.getSort()==null?0:menu1.getSort()) - (menu2.getSort()==null?0:menu2.getSort());
    }).collect(Collectors.toList());
    return level1Menus;
}

//递归查找所有菜单的子菜单
private List<CategoryEntity> getChildrens(CategoryEntity root,List<CategoryEntity> all){
    List<CategoryEntity> children = all.stream().filter(categoryEntity -> {
        return categoryEntity.getParentCid() == root.getCatId();
    }).map(categoryEntity -> {
        //1、找到子菜单
        categoryEntity.setChildren(getChildrens(categoryEntity,all));
        return categoryEntity;
    }).sorted((menu1,menu2)->{
        //2、菜单的排序
        return (menu1.getSort()==null?0:menu1.getSort()) - (menu2.getSort()==null?0:menu2.getSort());
    }).collect(Collectors.toList());
    return children;
}
```

#####   1.1.4.2.2、跨域问题研究

首先理解什么是跨域，就是只两个通信协议、ip、端口，必须要保持一直，一旦一个不一致就是跨域

比如 http://localhost:88/ 通信协议是http协议，localhost就是ip，端口就是88，这三个必须要保持一致

![理解什么是跨域](.\img\88.png)



跨域问题研究：

https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/CORS

![跨域请求的预校验](.\img\89.png)

在点击查看调用接口，发现调用方法有个`OPTIONS`报错，这个报错就是上面提到的发送预校验给拦截了，原理在文档以下内容部分：

原理：

![简单请求](.\img\90.png)

预检请求

![预检请求](.\img\91.png)

附报错截图：

![OPTIONS拦截](.\img\92.png)



​	上面的演示就是其实发起的是一个POST请求（后面会说），它属于简单请求(`get,head,post`)。但是除了请求方法，简单请求还要满足以下这些，比如发送的请求的内容类型。必须是这三种之一`text/plain, multipart/form-data, application/x-www-form-urlencoded`，上面请求报文它其实是一个`application/json`，这是后话。这个请求内容格式为`application/json`它就是不属于简单请求，对于非简单请求，需要发送一个预检请求，而这个预检请求就是`OPTIONS `方式。

​	所以跨域流程就是这样的。浏览器假设发送了一个非简单请求，首先要发一个options请求就是先锋部队先找服务器问一下，这个服务器允不允许浏览器跨域访问，如果服务器访响应了允许，那我们浏览器才会访问发送他真正的请求，过去拿到响应数据。而此时我们现在的服务器是不允许的，所以我们options请求就没有发过去。

#####   1.1.4.2.3、跨域问题解决方案



**方案一、解决跨域-（一）使用nginx部署为同一域**

![方案一使用NG](.\img\93.png)

我们使用nginx把他们转化为同一个域，具体操作：

现在这有一台nginx服务器，我们将我们的前端项目也部署到里边，然后将我们后台的网关也让nginx代理过来。之后我们浏览器想要访问我们这个前端项目，我们就不访问前端项目的地址了，我们直接访问nginx的地址。那么只要是静态请求默认都代理给我们的前端项目，那我们都知道我们的动态请求都会加上API，那只要我们再来访问动态请求。那么还是发给nginx，nginx一看带了API它动态的再来转给我们的网关，也就是反向代理给我们的网关，网关再来转到其他服务。那我们就可以利用第一种方式。从头到尾访问路径的都是nginx的服务地址。nginx配置好我们反向代理相关的内容把它们转化为同一个域，我们就不跨域了。



因为方案一需要配置nginx，目前还用不到，所以采用方案二

**方案二、解决跨域-（二）配置当次请求允许跨域**

![配置跨域的请求头](.\img\94.png)

因为我们的请求有多种，如果每个请求都要单独去配置相应头过于麻烦，所以写一个filter类。因为所有的服务都是访问网关，所以直接网关配置filter就行

```java
@Configuration
public class GulimallCorsConfiguration {

    @Bean
    public CorsWebFilter corsWebFilter(){
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();

        CorsConfiguration corsConfiguration = new CorsConfiguration();

        //1、配置跨域
        corsConfiguration.addAllowedHeader("*"); //允许所有头
        corsConfiguration.addAllowedMethod("*"); //允许所有请求方法
        corsConfiguration.addAllowedOrigin("*"); //允许请求来源可以跨域
        corsConfiguration.setAllowCredentials(true); //允许携带cookie跨越

        source.registerCorsConfiguration("/**",corsConfiguration);// registerCorsConfiguration：注册跨域的配置，/**表示任意路径
        return new CorsWebFilter(source);
    }
}
```

这里有个小问题启动项目后，前端请求还是报错了，如下问题：

```json
Access to XMLHttpRequest at 'http://localhost:88/api/sys/login' from origin 'http://localhost:8001' has been blocked by CORS policy: The 'Access-Control-Allow-Origin' header contains multiple values 'http://localhost:8001, http://localhost:8001', but only one is allowed.
```

![请求后出现多个请求头报错问题(header contains multiple values)](.\img\95.png)这个原因是因为，renren-fast它自己也配置了跨域配置，这个要给注释掉才可以

##### 1.1.4.3.5、菜单拖拽功能

一、拖拽节点功能 ﻿

1. 可拖拽节点 

![拖拽组件](.\img\102.png)

- 实现方式：通过设置draggable属性为true开启节点拖拽功能，默认值为false
- 代码示例：`<el-tree :draggable="true">`，该属性会使整个树形组件变为可拖拽状态
- 参照示例：Element UI官方文档中的"可拖拽节点"示例，展示了节点拖拽的基本效果

2. allowDrop属性 

![allowDrop属性](.\img\103.png)

- 功能作用：用于判断节点能否被放置在目标位置，通过返回true/false控制拖拽行为
- 参数说明：
  - draggingNode：当前被拖动的节点对象
  - dropNode：目标放置位置的节点对象
  - type：放置位置类型，包含三种值：
    - 'prev'：放置在目标节点前
    - 'inner'：插入至目标节点内部
    - 'next'：放置在目标节点后
- 业务限制：分类层级不能超过3级，需要计算节点深度进行控制

3. 拖动效果展示

![拖拽效果](.\img\104.png)

- 视觉反馈

  ：

  - 向前拖动时会出现横线标识位置
  - 向后拖动同样显示横线
  - 拖入节点内部时会有特殊标识

- 层级限制：业务要求分类最多只能有3级，超过层级的拖拽需要被禁止

4. 计算当前节点总层数

![计算当前节点总层数](.\img\105.png)

- 计算方法：
  - 递归遍历所有子节点，求出最大深度
  - 使用公式：deep = maxLevel - currentNode.catLevel + 1
- 关键属性：
  - catLevel：节点当前层级
  - children：子节点数组
  - level：节点在树中的层级位置
- 实现逻辑：
  - 初始化maxLevel为0
  - 遍历子节点，比较并更新maxLevel
  - 递归调用计算每个子节点的深度

5. 页面效果展示

![页面效果调试](.\img\106.png)

- 调试信息：
  - 打印allowDrop方法的三个参数
  - 输出当前节点的深度计算结果
- 实际限制：
  - 手机通讯节点(深度3)不能拖入运营商节点(深度2)
  - 厨房小电节点不能拖入手机通讯节点
- 错误处理：递归调用时需要使用this.countNodeLevel确保正确绑定

6. 最终效果展示 

![最终展示效果](.\img\106-1.png)

- 成功条件：
  - 当type="inner"时：deep + dropNode.level ≤ 3
  - 其他情况：deep + dropNode.parent.level ≤ 3
- 限制效果：
  - 手机节点不能拖入家用电器内部
  - 手机通讯可以拖入家用电器
  - 厨房小店不能拖入手机通讯

二、知识小结

关键步骤与实现逻辑
1. 开启拖拽功能
在 `<el-tree>`组件中设置 draggable="true"，启用节点拖拽。
拖拽时可通过 allow-drop属性控制节点是否可被放置到目标位置。
2. 放置规则判断（allow-drop函数）
函数参数：
draggingNode：当前被拖拽的节点。
dropType：放置位置类型（prev前、inner内、next后）。
dropNode：目标节点（放置到其前后或内部）。
核心规则：
被拖拽节点的总层级 + 目标位置的层级 ≤ 3（三级分类限制）。
3. 计算被拖拽节点的总层级
递归统计子节点最大深度：
若节点有子节点（children.length > 0），递归遍历所有子节点，记录最大深度（maxLevel）。
当前节点的总层级 = maxLevel - 当前节点层级 + 1。
示例：
若被拖拽节点的子节点最大深度为 3，当前节点层级为 2，则总层级 = 3 - 2 + 1 = 2 层。
4. 结合目标位置判断合法性
放置到目标节点内部（inner）：
被拖拽节点总层级 + 目标节点层级 ≤ 3。
放置到目标节点前后（prev/next）：
被拖拽节点总层级 + 目标节点父层级 ≤ 3。

## 2.3、云存储使用

一、文件存储

1. 文件存储简介

- 单体应用存储方式：文件直接保存在项目部署服务器的指定目录下，请求和响应都在同一台服务器完成
- 分布式存储问题：多台服务器部署时，文件上传到A服务器后，下次请求可能负载均衡到B服务器导致文件找不到
- 解决方案：使用统一文件存储系统，所有服务读写同一位置的文件
- 自建方案：FastDFS、FTP等，但搭建复杂、维护成本高、前期投入大
- 云存储优势：即开即用、专业维护、按量计费、弹性扩展

2. 阿里云对象存储

1）对象存储简介

- 全称：Object Storage Service (OSS)
- 用途：存储项目中的图片、音频等文件
- 特点：海量、安全、低成本、高可靠（99.9999999999%数据可靠性）
- 访问方式：通过RESTful API在互联网任何位置存储和访问
- ![img](.\img\166.png)

2）对象存储开通

- 开通步骤：
  - 登录阿里云官网
  - 完成实名认证（首次使用需绑定手机号）
  - 搜索并开通OSS服务
  - 创建Bucket（存储空间）

![img](.\img\167.png)

二、用户上传文件到oss

- 普通上传方式

  - 流程：
    - 用户上传文件到应用服务器
    - 服务器使用Java代码将文件传到OSS
  - 缺点：文件经过应用服务器，占用带宽影响性能

  ![img](.\img\168.png)

- 服务端签名后直传（推荐）

  - 流程：
    - 前端向服务器请求上传策略(Policy)和签名
    - 服务器用AccessKey生成签名返回给前端
    - 前端直接上传文件到OSS，携带签名验证
  - 优势：文件不经过应用服务器，避免带宽瓶颈
  - 安全性：不暴露AccessKey，使用临时签名授权

```java
/**
     * 获取签名
     * @return
     */
@RequestMapping("/oss/policy")
public R policy(){
    // 构建基础信息
    String host = "https://" + bucket + "." + endpoint;
    //我们后期上传到阿里云的都是带有时间格式的目录的，所以需要指定上传的文件目录名称
    String format = new SimpleDateFormat("yyyy-MM-dd").format(new Date());
    String dir = format + "/";
    //获取本地环境的oss对象
    // 填写Bucket所在地域。以华东1（杭州）为例，Region填写为cn-hangzhou。
    String region = "cn-beijing";
    Map<String, Object> respMap = null;
    OSS ossClient = null;
    try {
        // ===== 2. 构建 OSS Client（V4）=====
        ClientBuilderConfiguration clientBuilderConfiguration = new ClientBuilderConfiguration();
        clientBuilderConfiguration.setSignatureVersion(SignVersion.V4);
        EnvironmentVariableCredentialsProvider credentialsProvider = CredentialsProviderFactory.newEnvironmentVariableCredentialsProvider();
        ossClient = OSSClientBuilder.create()
            .endpoint(endpoint)
            .credentialsProvider(credentialsProvider)
            .clientConfiguration(clientBuilderConfiguration)
            .region(region)
            .build();
        // ===== 3. 构造 PostPolicy =====
        long expireTime = 30;
        long expireEndTime = System.currentTimeMillis() + expireTime * 1000;
        Date expiration = new Date(expireEndTime);
        PolicyConditions policyConds = new PolicyConditions();
        //限制文件大小
        policyConds.addConditionItem(PolicyConditions.COND_CONTENT_LENGTH_RANGE, 0, 1048576000);
        //限制上传目录前缀
        policyConds.addConditionItem(MatchMode.StartWith, PolicyConditions.COND_KEY, dir);

        String postPolicy = ossClient.generatePostPolicy(expiration, policyConds);
        byte[] binaryData = postPolicy.getBytes("UTF-8");
        String encodedPolicy = BinaryUtil.toBase64String(binaryData);
        String postSignature = ossClient.calculatePostSignature(postPolicy);

        //组装返回 oss信息
        respMap = new LinkedHashMap<String, Object>();
        respMap.put("accessid", System.getenv("OSS_ACCESS_KEY_ID"));
        respMap.put("policy", encodedPolicy);
        respMap.put("signature", postSignature);
        respMap.put("host", host);
        respMap.put("dir", dir);
        respMap.put("expire", String.valueOf(expireEndTime / 1000));
    } catch (Exception e) {
        throw new RuntimeException(e);
    } finally {
        // 安全关闭 OSSClient
        if (ossClient != null) {
            try {
                ossClient.shutdown();
            } catch (Exception e) {
                // 仅记录日志，不掩盖原始异常
                log.error("关闭 OSSClient 失败", e);
            }
        }
    }
    return R.ok().put("data",respMap);
}
```

```java
public class ListValueConstraintValidator implements ConstraintValidator<ListValue,Integer> {
    private Set<Integer> set = new HashSet<>();
    //初始化方法
    @Override
    public void initialize(ListValue constraintAnnotation) {
        int[] vals = constraintAnnotation.vals();
        for (int val : vals) {
            set.add(val);
        }
    }
    //判断是否校验成功
    /**
     *
     * @param value 需要校验的值
     * @param context
     * @return
     */
    @Override
    public boolean isValid(Integer value, ConstraintValidatorContext context) {
        return set.contains(value);
    }
}
```
